# Remote runner SSH boundary

ASB remote discovery treats the user's OpenSSH configuration as authoritative. The
frontend only enumerates concrete `Host` aliases (including bounded `Include` files)
for selection and records successful aliases in a mode-0600, bounded recent-connection
ledger. It never examines shell history or infers recency from `known_hosts` order.

After selection, OpenSSH resolves the complete configuration with `ssh -G`. The
connection is then spawned as an argument vector with normal host-key verification,
`-T`, and the fixed `asb remote-proxy --stdio --probe` command. No shell interpolation,
TCP listener, or user-provided remote command is permitted. Stdin/stdout carry the
versioned control protocol; stderr remains diagnostic-only.

Password prompts remain attached to the controlling terminal or OpenSSH agent. ASB
does not capture, persist, echo, or transmit passwords, passphrases, cookies, or
authorization headers.

Key enrollment is opt-in and confirmation-gated by the selected alias and displayed
fingerprint. Only a local Ed25519 public-key file is read. The fixed remote installer
atomically preserves the existing `authorized_keys`, adds a restricted
`command="asb remote-proxy --stdio"` entry with `restrict`, and keeps the directory
and file mode at 0700/0600. ASB never copies or logs a private key. Users can revoke
the displayed restricted entry from the target host; unrestricted shell keys require
a separate expert workflow and are not generated by this boundary.

The implementation is transport plumbing, not support evidence for any agent or
platform. Runner identity, version, capability, and reconnect cursor remain
authoritative in the runner protocol. Unsupported SSH implementations and missing or
outdated `asb remote-proxy` services fail closed.
